# YOLOps-Agent 面试讲法

## 简历短描述

独立完成一个面向目标检测流程的轻量级 YOLOps 工作台，使用 Vue 3 + FastAPI + SQLite/PostgreSQL，覆盖数据集管理、标注浏览、训练任务、模型归档和 Agent 辅助分析，重点解决训练项目中数据、训练与模型关系混乱的问题。

## 3 分钟项目介绍

这个项目的背景是，我不想只做一个“上传图片跑一次模型”的演示，而是想把目标检测项目里更真实的流程串起来，包括数据集版本、图片逐张查看、标注状态、训练任务管理、模型归档和结果分析。

技术上我用了 Vue 3 做前端工作台，FastAPI 做后端接口，训练部分对接 Ultralytics YOLO。数据库层保留了 SQLite 和 PostgreSQL 两种模式，当前更偏向单机演示版，所以默认推荐 SQLite。

我重点做了三块事情。第一块是数据和标注相关能力，包括数据集导入、版本管理、图片预览、标注框展示和标注工作台。第二块是训练和模型链路，把训练任务、项目、数据集和产出模型绑定起来，避免后面只看到一堆 run_id 不知道彼此关系。第三块是 Agent 分析页，让它基于当前项目上下文去看训练、模型和数据集，输出分析和下一步建议。

这个项目现在的定位不是多人生产系统，而是一个结构完整的工程演示版。它的价值在于展示我不是只会调用模型，而是会围绕一个真实流程去做前后端联动、状态管理、数据库设计和界面组织。

## 你做过的关键取舍

- 默认保留 SQLite，是为了单机演示和最终打包更轻
- PostgreSQL 没删，是为了说明项目具备继续升级到正式部署版的空间
- 当前训练任务还是后端进程内调度，没有强行上独立 worker，因为这个阶段目标是先保证闭环和可演示
- 没继续无限加功能，而是优先把项目、训练、模型三者的关系理顺

## 面试高频追问

### 1. 为什么做这个项目？

因为目标检测项目真正麻烦的地方通常不只是模型本身，而是数据集版本、标注状态、训练过程、模型归档和后续分析。我想做一个比“单次推理 demo”更完整的工程练习。

### 2. 为什么前端用 Vue，后端用 FastAPI？

Vue 3 适合快速搭建数据型工作台，组件化和页面组织都比较直接。FastAPI 对这种工具型后端很合适，接口定义清晰，开发效率高，也方便后面扩展训练、模型和数据集相关 API。

### 3. 为什么还保留 SQLite？

因为当前版本主要面向单机演示和本地运行。SQLite 不需要额外安装数据库服务，交付成本最低。以后如果做多人协作或服务化部署，可以切 PostgreSQL。

### 4. 你觉得这个项目现在最大的不足是什么？

训练和验证任务目前还是进程内线程调度，适合单机，不适合生产级任务系统。另外前端缓存层和自动化测试体系还不完整，所以现在更适合作为实习作品和工程演示版，而不是正式产品。

### 5. 如果继续做，你下一步会升级什么？

我会优先升级三件事：训练/验证任务拆成独立 worker，前端引入统一缓存和失效机制，以及把数据库迁移体系正规化。
