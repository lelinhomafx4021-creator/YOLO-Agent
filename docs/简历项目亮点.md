# YOLOps-Agent 简历项目亮点

这份文档只放简历和面试里最值得说的亮点，不展开实现细节。

## 1. 一句话项目描述

独立完成一个面向目标检测流程的轻量化 YOLOps 工作台，基于 Vue 3 + FastAPI + YOLO 构建，覆盖数据集管理、标注浏览、训练任务、模型归档和 Agent 辅助分析。

## 2. 简历里最值得写的亮点

- 跑通了项目、数据集、标注、训练、模型、Agent 分析的完整闭环
- 不是单次 YOLO 推理 demo，而是面向真实工程流程组织的工作台
- 采用前后端分离架构，前端负责工作台交互，后端负责业务管理与训练调度
- 资源本体落磁盘、元数据入库，理清了图片、标签、模型与业务关系
- 同时保留 SQLite 默认交付与 PostgreSQL 可切换方案，体现阶段性工程取舍
- 支持训练记录、模型归档、项目绑定与结果回看，增强了工程可复盘性
- 引入 Agent 分析页面，将训练、模型、数据集信息整合为可对话的分析助手

## 3. 可以直接放简历的写法

### 版本一：简历短描述

独立开发轻量化 YOLOps 工作台，基于 Vue 3、FastAPI、Ultralytics YOLO 构建数据集管理、标注浏览、训练任务、模型归档与 Agent 分析闭环，支持 SQLite 默认交付与 PostgreSQL 可切换方案。

### 版本二：偏工程能力

围绕目标检测项目的真实工程流程，独立完成数据集、标注、训练、模型和分析模块的前后端联动，理顺资源存储、业务关系、任务展示与结果复盘链路。

### 版本三：偏实习面试

完成一个单机演示型 YOLOps 工程项目，不只关注模型训练本身，而是重点解决数据版本、训练记录、模型归档与分析复盘之间的组织问题。

## 4. 面试时优先强调什么

- 我做的是工程闭环，不是单点功能
- 我有明确的技术取舍，不是一味堆技术
- 我知道项目当前适合什么场景，不适合什么场景
- 我能说清楚后续怎么升级，而不是把它包装成已经完全产品化

## 5. 不建议过度包装的点

- 不要说成生产级多租户平台
- 不要说成成熟自治 Agent 系统
- 不要把 SQLite 说成缺点本身
- 不要把页面数量当成核心亮点

## 6. 一句话总结

这个项目最能打动面试官的地方，是它体现了你能围绕一个真实目标检测流程做完整工程组织，而不只是会调用一个模型。
